# FAIR-style model: inputs, method, and results

_Generated by `python3 -m backend.model.export_results` · model version `2026-11-22-evidence-v1` · 10,000 trials · seed 20261124. Do not edit by hand; edit `backend/data/config.py` and re-run._

## 1. Method

- **Structure.** Each scenario combines event frequency, conditional success, and component-level primary and secondary loss. Launch-Day DDoS is measured per seven-day launch event; the other three scenarios are annual.
- **Formula.** Loss = material loss events x (primary loss + secondary-effect indicator x secondary loss).
- **Sampling.** Triangular low / most-likely / high inputs; 10,000 trials with fixed seed 20261124. Annual event counts use a Poisson draw on threat event frequency, thinned by conditional success.
- **Controls.** Each control multiplies only the factors it genuinely influences by (1 - effectiveness); effectiveness is sampled from its low / likely / high range and stacks multiplicatively. Baseline and residual runs share the same random draws, so differences come only from controls.
- **Cost basis.** Launch event view charges the full first-year cost (one-time + annual + per-launch) to the launch event, a conservative choice. Annual view uses annual cost + one-time cost amortized over 3 years + per-launch cost x 1 launch per year.
- **Timing.** Inputs are an ex-ante estimate for the Nov 19-25, 2026 launch window. Launch-week observations (Rockstar services held; PSN disruptions on Nov 18-19) are used as calibration evidence. The same structure applies to the later GTA VI online and PC launches.
- **Evidence classes.** Public fact, Derived value, Team estimate, Model assumption.
- **Disclaimer.** This is a team-designed FAIR-style model for decision support, not an official Open FAIR, NIST, or MITRE assessment. It makes no claim about Take-Two's private controls or architecture.

Launch-event trial (Launch-Day DDoS):

```
attack     = U1 < attackProbability
material   = attack and U2 < conditionalSuccess x control multipliers
primary    = outageHours x hourlyRevenueAtRisk x lostRevenueFraction
             + responseCost + emergencyInfrastructure + refundsMakeGoods + supportSurge
secondary  = (U3 < secondaryProbability) x (reputationLoss + partnerLegal)
loss       = material x (primary + secondary)
```

Annual trial (other three scenarios): `attempts = PoissonInverseCDF(U1, threatEventFrequency)`, each attempt succeeds with `conditionalSuccess`, and `loss = successes x (primary + secondary indicator x secondary)`. Multiple events in one trial reuse that trial's sampled magnitudes (model assumption).

Control economics: expected risk reduction = baseline mean - residual mean; net benefit = reduction - comparable-period cost; ROSI = net benefit / cost; cost of inaction = avoidable expected loss; tail-risk reduction = baseline P95 - residual P95. Annualized cost = annual + one-time / 3 + per-launch x 1.

Priority score (100 points): expectedLossReduction 35, reductionPerDollar 25, p95Reduction 20, scenarioCoverage 10, feasibilityConfidence 10. 60+ = Priority 1 (implement before launch), 40-59 = Priority 2 (implement next), below 40 = Priority 3 (evaluate or monitor). Scored on the first-year view (one launch event + one year of annual scenarios).

## 6. Attack paths

**Launch-Day DDoS:** 01 Target and dependency reconnaissance -> 02 Attack infrastructure prepared -> 03 Network-layer flood begins -> 04 Application or service exhaustion -> 05 Service degradation and cascading failure -> 06 Detection, response, and recovery -> 07 Business loss event

**Build & Source Code Theft:** 01 Social engineering of staff or a vendor -> 02 Valid account used on collaboration and build tools -> 03 Discovery and collection from repositories -> 04 Exfiltration of builds, footage, or code -> 05 Public leak or extortion becomes a loss event

**Insider or Contractor Leak:** 01 Trusted access to confidential content -> 02 Collection from repositories and chat -> 03 Disclosure outside the company

**Fake Downloads & Phishing:** 01 Fake demo, PC build, or giveaway staged -> 02 Player runs a malicious installer -> 03 Stolen credentials used for account takeover

## 8. Validation

- `python3 -m unittest discover -s backend/tests -v` runs model, API, and data-integrity tests.
- Independent check: for every scenario the 200,000-trial Monte Carlo mean is within 4% of a closed-form expectation computed from triangular means (E[frequency] x E[success] x (E[primary] + E[secondary probability] x E[secondary])).
- Common random numbers: residual loss is never above baseline loss in any trial, for every scenario with every applicable control on.
- Reproducibility: the same seed returns identical metrics, histograms, and sensitivity results.
- Integrity: every input has a source, evidence class, rationale, confidence, owner, and reviewer; every control effect targets a real input; attack steps and controls reference each other in both directions.

## 9. Limitations

- Most loss magnitudes are team estimates anchored to public figures, not Take-Two data; ranges are wide on purpose.
- Inputs are sampled independently; real losses are correlated (a longer outage also raises refunds and support). This likely understates the tail.
- Control effectiveness ranges are team estimates informed by vendor and industry evidence, not measured Take-Two performance.
- Stacking controls multiplicatively assumes independent effects; overlapping controls may deliver less combined benefit.
- Launch-week observations (Nov 19-22, 2026) were used to calibrate revenue at risk and baseline capacity, so the DDoS figures are not a pure forecast.
